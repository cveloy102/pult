# Независимые релизы

Один репозиторий, две отдельные сборки. Публикация только по компонентному тегу после проверок.

## Android

Перед первым релизом владелец создаёт постоянный release-keystore, сохраняет его резервную копию вне репозитория и добавляет GitHub Actions secrets:

- `ANDROID_KEYSTORE_BASE64` — keystore в Base64.
- `ANDROID_STORE_PASSWORD`.
- `ANDROID_KEY_ALIAS`.
- `ANDROID_KEY_PASSWORD`.

Не заменяйте release-ключ при каждом выпуске: уже установленное приложение должно обновляться APK с той же подписью. Не публикуйте ключи в репозитории или релизах.

Тег `android-v0.1.0` запускает Android workflow. Он проверяет формат версии, вычисляет возрастающий versionCode (`major * 1000000 + minor * 1000 + patch`), собирает и подписывает APK, запускает lint и публикует APK, compatibility.json и SHA256SUMS. Компоненты версии minor/patch — меньше 1000.

При ненастроенных secrets workflow останавливается; неподписанный или debug APK не публикуется как стабильный релиз.

Локальная релизная сборка использует `PULT_KEYSTORE`, `PULT_STORE_PASSWORD`, `PULT_KEY_ALIAS`, `PULT_KEY_PASSWORD` и Gradle-параметры `-PversionName=X.Y.Z -PversionCode=N`.

Для первой версии локальный ключ уже создан в игнорируемой папке `work/signing/`. Скрипт `scripts/build-android-release.ps1` повторно использует его. Пароль защищён Windows DPAPI и читается только в профиле создавшего его пользователя. Нужна резервная копия самого ключа и отдельно восстановимого пароля перед переустановкой Windows; копии файла DPAPI недостаточно для переноса на другой ПК. GitHub secrets пока не настроены. Для будущих CI-релизов используйте именно этот ключ, чтобы обновлять первый установленный APK.

## Windows

Тег `agent-v0.1.0` запускает только Windows workflow: тесты, self-contained публикация .NET для win-x64 и архив с инструкцией запуска. Установка .NET пользователю не требуется.

Агент первой версии открывает страницу проверенного компонента-релиза и предлагает скачать архив. Файлы не исполняются и не заменяются автоматически. Для встроенного Windows-обновлятора в будущем нужен подписанный манифест, отдельный процесс замены и откат.

## Совместимость

Версия продукта не равна версии протокола. Android 1.2.0 может работать с агентом 1.0.0, если оба используют протокол 1. UI/тема/виджеты не требуют переиздания агента.

Сначала проверяются команды и возможности поддерживаемого протокола. При добавлении команды нужно отдельно обновить Windows-реализацию, а Android должен скрывать её на агенте, который её не объявляет. При смене основной версии протокола потребуется соответствующее обновление обеих сторон.

Для публикации тега:

```text
git tag android-v0.1.0
git push origin android-v0.1.0
```

Для Windows используются `agent-v…`. Не публикуйте теги до готовности соответствующего пакета и ключей. CI-проверки обычных коммитов не выпускают релизы.
