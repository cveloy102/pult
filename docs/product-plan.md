# Пульт — продукт и дизайн

Статус: первая версия реализована. Android 12+ и Windows 10/11 x64. Три темы доступны в настройках; агент и Android выпускаются независимо. Сборки и автоматические проверки выполнены; проверка на физическом POCO F7 ещё требуется.

## Зафиксировано пользователем

- Название приложения: «Пульт».
- Android-приложение и фоновый агент Windows.
- Работа в локальной сети; для доступа из дома наружу уже есть другой инструмент.
- Выключение и перезагрузка с подтверждением.
- Блокировка экрана.
- Таймеры с возможностью отменить их с телефона.
- Управление громкостью и команда play/pause.
- Курсор отложен. Обложки, информация о треке и другие медиаданные не нужны.
- Дизайн Android, агента и виджета должен быть согласован до начала разработки.
- Нужны три визуальные концепции: в стиле https://tg.hl100.ru и две альтернативные.
- Исходники должны храниться в Git; обсуждается публичный GitHub и обновление из Releases.
- Выбор темы через пункт «Тема оформления» в настройках.

## Предложение для согласования

### Агент Windows

Фоновое приложение пользователя с автозапуском и значком в трее. Работает в интерактивном сеансе пользователя, чтобы управлять звуком и блокировкой. Закрытие окна сворачивает его в трей, завершение агента — отдельное действие.

Небольшое окно: обзор, привязанные телефоны, настройки, обновления. Обзор показывает сеть, подключённый телефон и активный таймер. В трее: открыть окно, подключить телефон, проверить обновления, завершить агент.

### Android

Главный экран: состояние подключения, выключение, блокировка, перезагрузка, активный таймер с отменой, громкость и play/pause.

Отдельный экран таймера: действие, минуты, быстрые значения 15/30/60. Предлагается один активный таймер в первой версии; замена существующего должна быть явно подтверждена. Количество таймеров ещё не согласовано.

Настройки: подключение к ПК, версия приложения, проверка обновлений. Целевые версии Android определить по телефону пользователя до выбора минимального API.

Команда play/pause — системная медиаклавиша. Пульт не утверждает, что знает состояние конкретного плеера: без интеграции с медиасессиями кнопка имеет нейтральный смысл «плей / пауза». Изменение иконки в макете — демонстрация взаимодействия, не обещание синхронизации с плеером.

### Виджеты

- «Питание»: выключить и заблокировать, ориентир 2×1.
- «Пульт»: те же кнопки плюс громкость −/+, ориентир 4×2.

Конкретные размеры проверить на реальном лаунчере: сетка, системные поля и размеры ячеек отличаются. Выключение открывает небольшое окно подтверждения, блокировка выполняется сразу. Недоступные команды имеют явное состояние. Виджет выполняет короткий запрос без постоянно работающего Android-сервиса.

### Подключение и таймеры

Предпочтительно QR-привязка с ручным кодом как запасным способом. В макете показан ручной код; сканируемый QR пока не реализован. Привязка разрешается только из окна агента и ограничена по времени. Шифрованное соединение с проверкой идентичности ПК, отдельные учётные данные для каждого телефона и отзыв доступа.

Обнаружение ПК в локальной сети; ручной адрес как запасной путь. Статус не должен выдавать сетевую недоступность за достоверное выключение ПК.

Таймер исполняется на ПК независимо от телефона, сохраняется на диск. Пропущенные после загрузки таймеры выключения/перезагрузки не выполняются внезапно. Правила поведения при сне компьютера и переводе часов ещё нужно определить. Подтверждение отмены показывается только после ответа агента.

Повторная отправка опасной команды после таймаута должна использовать идентификатор запроса и защиту от повторного выполнения. Ошибка сети не должна автоматически повторять выключение, перезагрузку или toggle play/pause.

## Дизайн-концепции

- «Сигнал»: графит, молочный текст, красный акцент, моноширинная типографика, прямые грани, тонкие разделители. Отсылка к HL100 без копирования маски и брендинга fsociety.
- «Тихий»: тёплая светлая поверхность, глубокий зелёный акцент, мягкие формы, спокойная типографика, более бытовой характер.
- «Орбита»: тёмная синяя поверхность, холодный светлый акцент, крупная кнопка выключения, таймер выше действий, медиаблок как отдельная зона.

В каждой концепции показаны Android, агент, трей и два виджета. Макеты работают только с демонстрационными данными и не выполняют команды на ПК. Это первый раунд выбора направления; выбранную концепцию предстоит довести и проверить на телефоне.

## Темы оформления

В настройках Android и агента Windows — пункт «Тема оформления» с выбором «Сигнал», «Тихий», «Орбита» и предпросмотром. Выбор применяется сразу, сохраняется и переживает обновление приложения. Виджеты наследуют тему Android-приложения и обновляются при её смене. На ПК тема выбирается независимо от телефона.

Концепции рассматриваются как визуальные направления для тем; функциональность одинакова. Общую структуру экранов предстоит согласовать, чтобы смена оформления не заставляла заново искать действия. Макеты предыдущего раунда ещё не дополнены экраном выбора тем.

## Предлагаемый стек

Android: Kotlin, Jetpack Compose; виджеты — Android AppWidget/Glance после проверки требований к оформлению. Windows: C#/.NET, компактная WPF-оболочка и значок в трее. Обмен обычными командами по HTTPS; постоянное соединение для актуального состояния при открытом приложении при необходимости. WebSocket для движений мыши сейчас не нужен, поскольку курсор исключён.

## Предлагаемая политика версий и обновлений

Один публичный репозиторий для Android, агента, описания протокола и документации. Публичность, имя репозитория и лицензия требуют выбора пользователя; удалённый репозиторий ещё не создан и не подключён.

Версии Android и Windows независимы. Теги вида `android-v1.0.0` и `agent-v1.0.0`, отдельные файлы релизов и журнал изменений. Начальный поддерживаемый канал — stable; экспериментальные релизы только вручную.

Пример: Android 1.1.0 может выйти и работать с агентом Windows 1.0.0. Изменения оформления, виджетов и Android-ошибок не требуют нового релиза Windows.

В репозитории будут отдельные процессы GitHub Actions для публикации Android и Windows. Тег `android-v1.1.0` запускает проверки Android, сборку, подпись APK и создаёт Android-релиз; Windows-пакет при этом не выпускается. Тег `agent-v1.0.1` аналогично выпускает только агент. Публикация релиза — отдельное осознанное действие после прохождения проверок.

Каждая часть ищет собственные стабильные релизы по компоненту, исключая drafts/prereleases, сравнивает собственную версию и читает метаданные совместимости. Нельзя использовать общий «latest release» репозитория без фильтра: последним мог выйти другой компонент. При этом фильтрация должна учитывать пагинацию списка релизов.

Перед управлением агент сообщает версию протокола и поддерживаемые команды. Новые возможности приложения, которые отсутствуют в старом агенте, показываются недоступными с объяснением требуемого обновления; имеющиеся совместимые функции продолжают работать. При полностью несовместимой основной версии протокола управление блокируется с понятным указанием, какую часть обновить. Проверки релиза должны покрывать актуальное приложение с ранее выпущенными поддерживаемыми агентами и наоборот.

Протокол имеет отдельную версию и объявленные возможности. Обычные обновления не требуют одновременного обновления обеих частей. Несовместимость показывается до отправки команд с указанием, какую часть обновить. Проверку совместимости включить в релизные проверки.

GitHub Releases хранит подписанный APK Android и установщик/архив агента. Проверка новых версий не должна влиять на управление по LAN при отсутствии интернета.

Android: найти релиз, показать изменения, скачать и открыть системную установку по действию пользователя. Для обычного приложения не закладывать тихую установку. Один постоянный release-ключ подписи APK должен храниться вне репозитория с резервной копией.

Windows: найти релиз, показать изменения, скачать проверенный пакет, обновить после согласия пользователя. Первую реализацию можно сделать через установщик; полноценное обновление с отдельным helper-процессом и откатом — отдельная работа, которую нельзя считать готовой только из-за ссылки на GitHub.

Проверка SHA-256 выявляет повреждение файла; сама по себе она не доказывает автора пакета. Для встроенного обновлятора агента предусмотреть подписанный манифест с закреплённым публичным ключом. Публичные сертификаты, хеши и исходники допустимы в Git; приватные ключи, токены привязки, адреса домашней сети и локальные настройки — нет.

Предложение по поддержке: актуальная стабильная версия каждого компонента, исправления в ней; совместимость протокола сохранять в пределах текущей основной версии. Конкретные минимальные Android/Windows и архитектуры определить перед реализацией.

## До начала разработки

1. Выбрать дизайн-направление и изменения для приложения, агента и обоих виджетов.
2. Уточнить версии Windows/Android и необходимость двух виджетов.
3. Утвердить число активных таймеров и поведение при сне ПК.
4. Выбрать имя/публичность репозитория и лицензию.
5. Зафиксировать совместимость и минимальный сценарий обновления обеих частей.
